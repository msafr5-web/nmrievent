# nmrievent

منصة رقمية متكاملة لتصميم وإدارة الفعاليات والمؤتمرات والمعارض في المملكة العربية السعودية، مبنية وفق وثيقة متطلبات المنتج (PRD).

## الوحدات المنفذة

| الوحدة | المسار | الوصول |
| --- | --- | --- |
| البوابة العامة: الرئيسية، معرض الأعمال بالفلترة، الخدمات، المدونة، من نحن، تواصل | `/` `/portfolio` `/services` `/insights` ... | عام |
| نظام طلبات العروض الذكي: 5 خطوات + حاسبة تكلفة لحظية (FR-01)، يُحفظ في CRM | `/rfq` | عام |
| بوابة تسجيل الكوادر: بيانات ← رمز OTP من 4 أرقام ← بطاقة QR | `/join` | عام |
| لوحة الإدارة العليا: المؤشرات، المشاريع، قاعدة الموظفين، الإسناد وإصدار QR، خط المبيعات CRM | `/admin` | مدير |
| لوحة العمليات الميدانية: الورديات، التحضير الجغرافي واليدوي، الحشود، المواقف (FR-03) | `/ops` | فريق ميداني / مدير |
| بطاقة تحضير الموظف: QR وتسجيل الحضور والانصراف بالموقع | `/badge/[token]` | رابط موقّع |
| بوابة العملاء: متتبع المراحل (FR-02)، الاعتمادات والتوقيع الرقمي، التقارير، التشغيل المباشر | `/portal` | عميل / مدير |
| الدخول الموحد بثلاثة أدوار (JWT) | `/login` | عام |

**بيانات الدخول في التطوير:** العميل `NMR-26-DEMO1` / `client@example.com` · الفرق الميدانية `ops123` · الإدارة `admin123` (في الإنتاج تُضبط من متغيرات البيئة).

## التقنيات

- Next.js 15 (App Router) + React 19 + TypeScript
- Tailwind CSS 3 بنظام ألوان قائم على متغيرات CSS (`src/app/globals.css`)
- خطوط IBM Plex Sans Arabic للنصوص و Reem Kufi للعناوين
- zod للتحقق من البيانات، jose لجلسات JWT، qrcode لبطاقات QR
- Vitest لاختبارات الوحدة، و GitHub Actions للتكامل المستمر، و Docker للنشر

## التشغيل

```bash
npm install
cp .env.example .env.local   # عدّل رقم واتساب ورابط الموقع
npm run dev                  # http://localhost:3000
npm test                     # اختبارات الوحدة
npm run build && npm start   # نسخة الإنتاج
docker build -t nmrievent .  # صورة الحاوية
```

## هيكل المشروع

```
src/
├── app/            الصفحات والمسارات وواجهة /api/rfq
├── components/     مكونات الواجهة (Header, RfqConfigurator, PortfolioExplorer, ...)
├── content/        المحتوى (المشاريع، الخدمات، المقالات) — طبقة جاهزة للاستبدال بـ Headless CMS
├── lib/            حاسبة التكلفة، مخطط طلب العرض، جلسات JWT، حساب المسافة الجغرافية
├── server/         طبقة البيانات (db.ts)، المصادقة ورموز QR الموقعة، التحقق، بيانات البداية
└── middleware.ts   حماية /admin و /ops و /portal حسب الدور
```

## تخصيص المحتوى

- **الأعمال والخدمات والمقالات** في `src/content/*.ts`. المحتوى الحالي توضيحي ويجب استبداله بأعمال حقيقية.
- **أسعار الحاسبة** في `src/lib/estimator.ts` (أسعار أساسية لكل نوع، معاملات المستوى والمدينة، والخدمات الإضافية).
- **استقبال الطلبات:** اضبط `RFQ_WEBHOOK_URL` لإرسال كل طلب إلى CRM أو خادم NestJS أو أداة أتمتة (n8n / Zapier) لإرسال تأكيد البريد وواتساب.

## ملاحظات مهمة

- التخزين الحالي ملف JSON في `.data/` (يحتاج خادمًا دائمًا مثل Docker). مخطط PostgreSQL المستهدف في `docs/schema.sql`.
- رمز OTP والإشعارات تُرسل عبر `NOTIFY_WEBHOOK_URL` إلى مزود البريد / WhatsApp Business API. بدونه، ومع `OTP_DEMO_MODE=true`، يظهر الرمز على الشاشة للعرض فقط.
- قراءات الحشود والمواقف يدوية أو محاكاة إلى حين ربط الحساسات.

## المراحل القادمة (وفق PRD)

1. ربط Headless CMS (Strapi) لمعرض الأعمال والمدونة، وصور وفيديو حقيقية.
2. نقل التخزين إلى PostgreSQL و Redis، وربط مزود البريد و WhatsApp Business API.
3. تخزين ملفات التقارير والتشفير في السكون للعقود والتوقيعات.
4. اختبار الأداء والأمان، ثم النشر داخل المملكة (AWS me-central-1 / STC Cloud) التزامًا بنظام PDPL.
